# Нормальный и аномальный режим фрезерного станка

Задание 2 «Классификация» по курсу ML in mechanics

Клименко Георгий, Санкт-Петербургский государственный университет

[Готовый отчёт](report.pdf) · [Инструкция по сборке](#как-пересобрать-отчёт)

## Что проверяем

Во время обработки детали датчик записывает ускорение станка по трём осям. Аномальная обработка может изменить силу и частоту колебаний. При смене операции или станка вибрация меняется и при нормальной работе. Поэтому в проекте проверяется, может ли модель по записи ускорения распознать аномалию и насколько хорошо она справляется на другом станке или в более поздний период.

Одна запись соответствует одному файлу HDF5. Метка `good` означает нормальную обработку, `bad` — аномальную. В наборе Bosch CNC Machining 1702 записи, из них 70 аномальных. Даже правило «всё нормально» даёт около 96 % верных ответов на всём наборе, хотя пропускает каждую аномалию.

## Как устроен эксперимент

Для каждой оси рассчитываются среднеквадратическое значение, стандартное отклонение, размах, эксцесс и энергии в четырёх полосах от 0 до 1000 Гц. Всего получается 24 признака. Код станка, операция и период служат для разбиения и разбора ошибок.

Сравниваются семь методов: DummyClassifier с ответом по самому частому классу, логистическая регрессия, ближайшие соседи (kNN), метод опорных векторов (SVM), решающее дерево, случайный лес и гистограммный градиентный бустинг.

| Проверка | Обучение и подбор | Отложенные данные |
|---|---|---|
| Обычный тест | 75 % записей M01 и M02 | Остальные 25 % записей M01 и M02 |
| Перенос на другой станок при лимите просмотров 5 % | Выбор модели по взаимной проверке M01 и M02 внутри их обучающей части | Все записи M03 |
| Перенос во времени | 75 % записей M01 и M02 за периоды до августа 2021 года | Ранний контрольный тест из оставшихся 25 % и отдельный тест на всех записях M01 и M02 за август 2021 года |

В сравнении по времени каждая модель обучается на ранней обучающей части. Затем её с одним и тем же порогом проверяют на раннем контрольном и августовском тестах.

Для обычного теста настройки моделей выбираются по средней AP на пяти стратифицированных разбиениях обучения. AP показывает, насколько высоко модель ставит реальные аномалии в списке подозрительных записей. Для тревоги нужен порог. Его выбирают по максимуму F1 на проверочных частях обучения, чтобы учесть и пропущенные аномалии, и ложные тревоги. Параметры заполнения пропусков и стандартизации оцениваются только на данных обучения соответствующего разбиения, в том числе внутри калибровки SVM.

Для переноса на другой станок модель выбирается отдельно. В обучающей части M01 и M02 по очереди используются для обучения и проверки. Параметры подбираются по средней AP, модель выбирается по средней полноте при лимите просмотров 5 %. При равенстве полноты учитывается AP. Выбранную модель обучают на всей обучающей части M01 и M02. Все файлы M03 отложены до итоговой оценки.

## Что получилось

- **Обычная проверка на M01 и M02.** По средней AP на обучающих разбиениях выбрали SVM. На обычном тесте её AP составила 0,996. На M03 с тем же порогом модель нашла все 9 аномалий и подняла 493 ложные тревоги. Это оценивает перенос модели, выбранной для обычного теста.
- **Проверка переноса при лимите 5 %.** По взаимной проверке станков выбрали логистическую регрессию с параметром C = 10 и средней полнотой 66 %. На M03 модель нашла 3 из 9 аномалий за 26 просмотров. Пропущено 6 аномалий, ложных тревог было 23.
- **Сравнение с простыми правилами.** Если случайно выбрать 26 записей из 539, в просмотр в среднем попадёт 0,43 аномалии. Для каждой из девяти аномалий шанс отбора составляет 26 из 539. Правило «всегда тревога» обнаруживает все 9, но требует просмотра всех 539 записей и даёт 530 ложных тревог.
- **Сравнение моделей на M03.** При таком же лимите лес обнаружил 7 аномалий за 24 просмотра, а бустинг — 7 за 26. Эти результаты описывают сравнение на M03. Для выбора модели переноса использованы только проверки M01 и M02. В пакетном эксперименте все 539 файлов M03 образуют одну партию. Если оценки на границе совпадают, вся группа остаётся вне очереди, поэтому лес использовал только 24 места. Размер рабочей партии можно задать по сменам.
- **Перенос во времени.** По средней AP на раннем обучении выбран бустинг. Его AP снизилась с 0,970 на раннем тесте до 0,840 в августе. В августе бустинг обнаружил 5 из 7 аномалий и дал одну ложную тревогу. У SVM AP снизилась с 0,964 до 0,633, а у случайного леса выросла с 0,979 до 1,000. Лес обнаружил все 7 аномалий без ложных тревог. Результат леса приведён для сравнения на августовском тесте. В этой выборке из 76 записей шесть аномалий относятся к M01 и одна к M02.

Полные таблицы, графики ошибок и объяснение рабочего порога приведены в [отчёте](report.pdf).

## Как пересобрать отчёт

### 1. Подготовить окружение

Команды ниже рассчитаны на Windows и PowerShell. Нужны Git, Python 3.14 и шрифты Times New Roman (`times.ttf` и `timesbd.ttf`). Для установки зависимостей и первой загрузки данных понадобится интернет.

```powershell
git clone https://github.com/st115592/ML-task2.git
cd ML-task2
python --version
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

Убедитесь, что `python --version` показывает `3.14.x`. Скрипт ищет шрифты в папке Windows Fonts. Если файлы шрифтов находятся в другом месте, задайте путь к их папке перед сборкой.

```powershell
$env:CNC_FONT_DIR = 'C:\путь\к\папке\со\шрифтами'
```

### 2. Запустить сборку

Из корня репозитория выполните одну команду.

```powershell
.\.venv\Scripts\python build_report.py
```

При первом запуске скрипт скачивает около 950 МБ данных Bosch в `.bosch/data`. При каждом запуске он сверяет все 1702 файла с контрольными суммами в [манифесте](bosch_manifest.tsv). Если в стандартном кэше какой-то файл отсутствует или не проходит проверку, скрипт загружает его заново.

Далее скрипт читает записи, рассчитывает признаки, подбирает параметры и пороги, обучает модели и оценивает их на отложенных данных. Таблицы и рисунки попадают в PDF из результатов этого запуска. Разбиения и случайные состояния зафиксированы в коде.

### 3. Найти результаты и проверить повторную сборку

- `report.pdf` в корне репозитория — отчёт, который создаёт скрипт.
- `build/metrics.csv` — метрики по моделям. Поле `sample` обозначает обычный тест (`ordinary`), перенос на M03 (`transfer`), отбор до 5 % на M03 всеми семью моделями (`transfer_review_models`) или моделью, выбранной по переносу M01/M02 (`transfer_review`), ранний контрольный тест (`time_early`) или августовский тест (`time_august`). В строках также указаны средняя AP и её разброс на разбиениях обучения, а также рабочий порог.
- `build/*.png` — рисунки, включённые в PDF.

Для проверки воспроизводимости можно удалить `report.pdf` и папку `build`, затем снова выполнить команду сборки. Установленные зависимости находятся в `.venv`, а скачанные исходные данные — в `.bosch/data`.

### Если данные уже скачаны

Можно использовать распакованный [архив зафиксированной версии Bosch](https://github.com/boschresearch/CNC_Machining/archive/d60581d6a3ab6015dcc5488c3d76112bb8e1bcb1.zip). Передайте путь к каталогу `data`, внутри которого находятся папки `M01`, `M02` и `M03`. С установленными зависимостями такая сборка работает без сети. Скрипт проверяет файлы по тому же манифесту.

```powershell
.\.venv\Scripts\python build_report.py --data 'C:\путь\к\CNC_Machining\data'
```

## Проверки кода

Тесты проверяют расчёт признаков, выбор порога, разделение выборок, предобработку внутри калибровки SVM и восстановление кэша данных.

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest
.\.venv\Scripts\python -m black --check --line-length 99 cnc_data.py download_data.py experiment.py figures.py report.py build_report.py test_calculations.py test_regressions.py
.\.venv\Scripts\python -m flake8 .
```
